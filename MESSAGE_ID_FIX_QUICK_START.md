## 🐛 Quick Troubleshooting

### Messages have temp: IDs forever

**Check:**
1. Is WebSocket connected? (DevTools → Network → WS)
2. Is server broadcasting IDs? (Check server logs for "cf_agent_message_ids")
3. Is client handling the broadcast? (Look for 🔄 emoji in console)

**Fix:**
- Restart server
- Clear browser cache
- Check AGENT_HOST setting in constants.js

### Still seeing duplicates

**Check:**
1. Server logs for `persistMessages` errors
2. Verify override is active (should see "[Chat.persistMessages] Success" in logs)
3. Check database for duplicate rows

**Fix:**
- Verify server.ts changes deployed
- Check `generateId` is imported
- Restart Durable Object (redeploy)

### PRIMARY KEY errors in server logs

**Problem:** `persistMessages` override not working

**Fix:**
1. Check server.ts lines 316-395 are uncommented
2. Verify `generateId` imported from 'ai' package
3. Check for TypeScript errors: `npm run build`
4. Redeploy server

## 🎓 Key Concepts

**Temp ID**: Client-generated ID for optimistic updates
- Format: `temp:user:1:12345` or `temp:assistant:2:67890`
- Used until server confirms

**Server UUID**: Permanent ID from server
- Format: Alphanumeric string like `clx7y2z3a0001`
- Generated by `generateId()` from 'ai' package
- Single source of truth

**ID Replacement**: Process of swapping temp → UUID
- Happens via WebSocket broadcast
- Type: `cf_agent_message_ids`
- Usually within 1 second
